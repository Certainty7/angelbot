# Lighthouse evidence

## Production, 2026-11-15 — the deployed hostname

Measured against `https://angel.aetherisnode.cloud/` and `https://aetherisnode.cloud/` over the
public internet (mobile preset, Lighthouse 13.6.0, headless Chrome). Three runs on the home page, one
on each other page.

| URL | Performance | A11y | Best practices | SEO | LCP | CLS | TBT |
|---|---|---|---|---|---|---|---|
| `angel.aetherisnode.cloud/` | **99** (93, 99, 99) | **100** | **100** | **100** | 1.9 s | 0 | 290 ms |
| `angel.aetherisnode.cloud/en/` | **98** | **100** | **100** | **100** | 1.4 s | 0 | 150 ms |
| `angel.aetherisnode.cloud/commands/` | **99** | **100** | **100** | **100** | 0.9 s | 0 | 100 ms |
| `aetherisnode.cloud/` | **100** | **100** | **100** | **100** | 0.9 s | 0 | 30 ms |

Every release target is met on the delivered site: performance ≥ 95, accessibility 100, best
practices ≥ 95, SEO 100, LCP under 2 s, CLS 0. `/commands/` — the page that could not hold 95 on the
shared build host — scores 99 here, which is the measurement that settles it: the earlier spread was
host contention, not the page.

Raw reports: `prod-home-1..3`, `prod-en`, `prod-commands`, `prod-portal` in this directory.

This host sets no long-lived cache headers (`cache-control: max-age=600` for every asset) and no
`HSTS`, so the numbers are a floor for this provider, not the site's ceiling. The cached/CDN path on
Cloudflare is expected to be equal or better; it is not claimed here because it has not been measured.

## Local, 2026-11-14 — the shared build host

Measured against `astro preview` serving `website/dist` — the same build Cloudflare Pages publishes —
on a **shared build host under load**. Three consecutive runs per page
on one identical build; the table reports the median and the spread, because the spread here is
larger than the distance between a pass and a miss.

| | Performance (median) | runs | A11y | Best practices | SEO | LCP | CLS |
|---|---|---|---|---|---|---|---|
| `/` (Arabic) | **96** | 98, 94, 96 | 100 | 100 | 100 | 2.1 s (stable) | 0 |
| `/en/` | **98** | 98, 94, 100 | 100 | 100 | 100 | 1.5–1.6 s | 0 |
| `/commands/` | **89** | 89, 99, 85 | 100 | 100 | 100 | 1.1–1.3 s | 0 |

Release targets: performance ≥ 95, accessibility 100, best practices ≥ 95, SEO 100, LCP < 2 s where
practical, CLS < 0.05, INP < 200 ms.

**Verdict, per page rather than as one number:**

- Accessibility, best practices and SEO meet their targets on every page in every run (100 each).
- `/` and `/en/` meet the performance target (medians 96 and 98), LCP stable at 2.1 s and 1.5 s.
- `/commands/` does **not** reliably meet it here: median 89 with an 85–99 spread, while its LCP stays
  at 1.1–1.3 s. The entire spread is Total Blocking Time (110 → 590 ms) on a page whose JavaScript is
  one deferred module indexing 68 rows; the same build scored 96 and 99 when the host was idle. This
  was recorded as an open gate rather than a pass, and the deployed hostname settles it: 99 on
  production (see above), so the spread was the build host, not the page.
- LCP on the Arabic home is 2.1 s against a 2 s soft target, with both above-the-fold faces
  preloaded and no render-blocking request left (both audits report an empty list). Unchanged by the
  hero correction and by the owner-tools section.

**Rejected experiment, kept in the record:** `content-visibility: auto` on the 68 rows was tried as a
way to shrink that long task. It made the page dramatically worse (medians 57 / 87 / 77, TBT 6.1 s on
the first run) because the intrinsic-size estimate forced repeated layout as rows were measured, so
it was reverted without keeping a flag or a config option. The stylesheet carries no trace of it.

## Method

```bash
bash website/scripts/build.sh                 # dist/ must exist
npm run preview -- --port 4321 --host 127.0.0.1 &
CHROME_PATH=<chromium from playwright> bash website/scripts/lighthouse.sh 4321
```

- Lighthouse **13.6.0** via `npx`, Chrome from the Playwright install, `--headless=new`.
- Default (mobile) preset; no throttling overrides beyond the preset.
- Run the script three times and compare before quoting a score on this host; a single run is not
  evidence here.
- Committed beside this file: one full pass (`home`, `en`, `commands` `.report.json`). The HTML
  reports are regenerated by the script and stay out of git; they carry nothing the JSON lacks.

## What this does not prove

- Not a field measurement: no real users, no real network, no CDN.
- Not reproducible to ±2 points on a contended host, which is why the spread is published.
- INP is not measurable in a lab run without interaction; the browser suite exercises the explorer's
  search, filters and copy paths instead and asserts no console errors.
- Deployed headers (CSP, HSTS, caching) are verified separately with `curl -I` against the real
  hostname, not by Lighthouse.
